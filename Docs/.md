# 📑 Git & GitHub Team Workflow: Comprehensive Guide

> 👑 **Pesan PM (Project Manager):** 
> *Halo tim! Dokumen ini adalah panduan resmi alur kerja (workflow) Git untuk proyek kelompok kita. Tolong dibaca, dipahami logikanya, dan diikuti urutannya dengan disiplin setiap kali mau ngoding biar kode kita aman dan bebas dari bentrok (merge conflict). Semangat!* 🚀

---

## ⚙️ 1. Persiapan Awal (Hanya Sekali di Awal)

Sebelum mulai mengetik perintah apa pun di terminal, pastikan Git di komputer lokal kalian sudah mengenali identitas akun GitHub kalian. Jika belum, akan muncul error *Author Identity Unknown*. 

Buka terminal/Command Prompt di folder proyek, lalu jalankan dua perintah ini:

```bash
# 1. Daftarkan Email GitHub Kalian
git config --global user.email "email-kalian@example.com"

# 2. Daftarkan Username GitHub Kalian
git config --global user.name "UsernameGitHubKalian"
```

> 📌 **Catatan Penting:** 
> Pastikan semua anggota tim sudah mengklik **"Accept Invitation"** (Terima Undangan Collaborator) yang dikirim oleh PM ke email atau melalui tautan repositori proyek kita di GitHub agar mendapatkan izin akses penuh (*Permission*) untuk melakukan `push`.

---

## 🔄 2. Alur Kerja Sehari-hari (Daily Workflow)

Alur kerja Git tim kita dibagi menjadi dua fase utama: **Sebelum Mulai Ngoding** (mengambil pondasi kode terbaru) dan **Setelah Selesai Ngoding** (mengunggah hasil kerja).

### 🛠️ FASE 1: Sebelum Mulai Ngoding (Ambil Kode Terbaru)
Wajib hukumnya melakukan langkah ini di terminal secara berurutan sebelum menyentuh baris kode apa pun, agar dasar kode yang kalian pakai selalu sama dengan kode terakhir yang divalidasi PM.

| Urutan Langkah | Perintah Git | Penjelasan Logika & Fungsi |
| :--- | :--- | :--- |
| **1. Balik ke Jalur Utama** | `git checkout main` | Pindah posisi/jalur dari branch tugas lama ke branch utama proyek. |
| **2. Tarik Update Terbaru** | `git pull origin main` | Mendownload semua kode baru yang sudah disetujui PM dari server GitHub ke laptopmu. |
| **3. Bikin Kamar Pribadi** | `git checkout -b nama-fitur-mu` | Membuat sekaligus otomatis pindah ke cabang (*branch*) baru khusus tugasmu (Misal: `git checkout -b fitur-login`). |

> ⚠️ **PERINGATAN KERAS:** 
> Jangan pernah mengedit atau mengetik kode di dalam branch `main`. Kamar `main` hanya boleh di-update melalui penarikan (`pull`) dari server. Selalu buat branch baru untuk setiap tugas!

---

### 🚀 FASE 2: Setelah Selesai Ngoding (Cara Upload Tugas)
Gunakan prinsip: **Bungkus paket dan beri label di laptop lokal terlebih dahulu, baru kirimkan paketnya terbang ke server GitHub.**

```bash
# Langkah 1: Cek posisi branch aktif (Pastikan nama branch tugasmu berwarna hijau / bertanda bintang *)
git branch

# Langkah 2: Bungkus semua file baru atau perubahan codingan ke dalam sistem pelacakan Git
git add .

# Langkah 3: Beri label/catatan ringkas pada paket (Tulis deskripsi jelas tentang apa yang kamu ubah/buat)
git commit -m "menyelesaikan fungsi pembagi kelompok dan file json tes"

# Langkah 4: Kirim paket ke GitHub (Gunakan perintah ini KHUSUS untuk push pertama kali setelah bikin branch baru)
git push -u origin nama-fitur-mu
```

> 💡 **Tips Hemat Waktu:**
> Setelah Langkah 4 sukses dilakukan sekali di awal, jalur koneksi (*upstream*) antara laptop dan GitHub sudah terbangun. Untuk pengiriman (`push`) kedua, ketiga, dan seterusnya di branch yang sama, kalian cukup mengetik **`git push`** saja.

## 🧠 3. Kamus Istilah Git & Penjelasan Logisnya

Biar gak ketuker dan paham esensi perintahnya, ini analogi simpel di balik istilah-istilah Git:

*   **`origin`** 📡: Nama panggilan pendek (alias) otomatis yang merujuk pada alamat URL server repositori GitHub utama kelompok kita.
*   **`git fetch origin`** 🔍: Menanyakan kabar/absen terbaru ke GitHub. Perintah ini hanya memperbarui catatan daftar branch di latar belakang sistem laptop tanpa mendownload atau mengubah file codingan lu saat itu juga.
*   **`git commit`** 📦: Mengunci dan membungkus hasil kerjaan di laptop sendiri. Kode **BELUM** masuk ke website GitHub.
*   **`git push`** 🚚: Mengirim paket yang sudah di-commit dari laptop lokal menuju server website GitHub kelompok.
*   **`Upstream Branch (-u)`** 🛰️: Proses mendaftarkan alamat tetap atau membangun jembatan permanen antara branch lokal di laptop dengan branch remote di GitHub, sehingga ke depannya cukup mengetik `git push` atau `git pull` tanpa perlu menulis nama branch panjang-panjang lagi.

## 👑 4. Sudut Pandang PM: Cara Menggabungkan Kode Anggota (Merge)

Sebagai PM yang menjaga kestabilan branch utama (`main`), **jangan pernah mengetik `git pull origin [nama-branch-anggota]` langsung saat lu sedang berada di branch `main` lokal.** Hal itu bisa membuat struktur file rusak, menimpa file secara paksa, atau memicu file kosong `0 bytes`.

Gunakan salah satu dari dua alur aman ini:

### Cara 1: Lewat Pull Request di Website GitHub (Sangat Direkomendasikan)
1. Setelah anggota tim melakukan `git push -u origin nama-branch`, buka website GitHub repositori proyek kalian.
2. Klik tombol kuning/hijau **"Compare & pull request"** yang otomatis muncul di halaman utama GitHub.
3. Review baris kodenya. Jika sudah aman dan tidak ada bentrok, klik **"Merge pull request"** lalu **"Confirm merge"**. (Kode resmi menyatu di website).
4. Buka terminal laptop lu, lalu sinkronkan laptop lu dengan ketik:
   ```bash
   git checkout main
   git pull origin main
   ```

### Cara 2: Lewat Perintah `git merge` di Terminal Lokal
Jika lu ingin langsung menggabungkan dan mengetes kodenya di VS Code lokal lu sebelum di-upload ulang:
```bash
# 1. Fetch info terbaru dari GitHub
git fetch origin

# 2. Pindah ke branch anggota untuk memastikan kodenya masuk penuh
git checkout nama-branch-anggota
git pull

# 3. Kembali ke main lokal lu
git checkout main

# 4. Gabungkan secara resmi kodenya ke main lokal lu
git merge nama-branch-anggota

# 5. Upload hasil gabungan yang sukses ke GitHub utama
git push origin main
```

## 🚨 5. Troubleshooting (Solusi Cepat Mengatasi Error Umum)

### 🔴 Kasus A: Muncul tulisan "Please commit your changes or stash them before you switch branches."
*   **Penyebab:** Lu mau pindah branch (`git checkout`) atau mau narik kode (`git pull`), tapi lu udah terlanjur ngedit kode di branch saat itu tanpa di-commit.
*   **Solusi Cepat:** Ketik **`git stash`** (untuk menyembunyikan dan mengamankan kerjaan lu sementara), lalu jalankan perintah pemindahan branch. Setelah lu sampai di branch tujuan yang baru, ketik **`git stash pop`** untuk memunculkan kembali ketikan lu tadi.

### 🔴 Kasus B: File hasil `pull` atau `checkout` kelihatan kosong (0 bytes) atau Error `MERGE_HEAD exists`
*   **Penyebab:** Terjadi kesalahan akibat *pull* silang antar branch secara paksa, membuat proses pemindahan data menggantung di tengah jalan.
*   **Solusi Cepat:** Batalkan status gantung dan bersihkan cache lokal dengan mengetik:
   ```bash
   git merge --abort
   git reset --hard HEAD
   ```

### 🔴 Kasus C: Kode di lokal anggota ada, tapi pas di-push ke GitHub isinya kosong atau bertulisan "Everything up-to-date"
*   **Penyebab:** Anggota tim langsung mengetik `git push` tanpa melakukan `git add .` terlebih dahulu, sehingga file kodenya berstatus *Untracked* (belum masuk radar pantauan Git).
*   **Solusi Cepat:** Suruh anggota tersebut mengetik **`git status`** di terminalnya untuk memastikan. Perbaikannya adalah wajib mengetik ulang: **`git add .`** \(\rightarrow\) **`git commit -m "pesan"`** \(\rightarrow\) **`git push`**.
